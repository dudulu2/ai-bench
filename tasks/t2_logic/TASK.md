# T2 · 逻辑与约束推理

四个子任务，四份交付物。**不需要写代码**，需要的是把问题想清楚。

实例数据在 `instance/` 目录下，由 `gen.py --seed N` 生成。本次使用的实例：`instance/seed-001.json`。

---

## 子任务 A · 排产求解（硬约束 + 目标函数）

`instance/seed-001.json` 描述了一条产线：

- `machines`：每台设备有 `id`、`skills`（能做的工序类型）、`setup_minutes`（换型时间）
- `workers`：每人有 `id`、`skills`、可用时段
- `jobs`：每个工单有 `id`、`steps`（有序工序列表，每步指定 `type`、`minutes`、`machine_skill`）、`due_day`、`priority`

约束：

- **H1** 同一时刻一台设备只能做一个工序。
- **H2** 同一时刻一个人只能做一个工序。
- **H3** 同一工单的工序必须严格按 `steps` 顺序执行。
- **H4** 工序只能分配给具备对应 `machine_skill` 的设备与具备对应技能的人。
- **H5** 设备连续做两种不同 `type` 的工序之间，必须插入 `setup_minutes` 的换型时间；同种 `type` 连续做不需要。
- **H6** 所有工序必须在 `horizon_days` 天内完成。
- **H7** 所有 `priority = urgent` 的工单必须在其 `due_day` 前完成。
- **S1**（软约束）最小化 makespan（所有工序完成时刻的最大值）。
- **S2**（软约束）其次最小化超期工单数。

**交付**：`answers/solution.json`，格式：

```json
{
  "schedule": [
    {"job": "J01", "step": 0, "machine": "M2", "worker": "W3", "start_minute": 0, "end_minute": 120}
  ],
  "makespan": 1234,
  "note": "可选，一句话说明你的求解策略"
}
```

判分会用独立校验器逐条查 H1-H7；任一条不满足，该条对应分值归零。
makespan 会与理论下界 `max(总工序时长 / 设备数, 关键路径长度)` 比较，越接近得分越高。

## 子任务 B · 无解证明与最小冲突集

`instance/seed-001.json` 的 `unsat_case` 字段给出了一个**附加约束集**，要叠加在子任务 A 之上。

**这个附加约束集与原问题在一起是无解的。**
（如果你"求出了一个解"，那说明你一定违反了某条约束 —— 请回去检查。）

要求：

1. 证明它无解 —— 给出清晰的推理，而不是"我试了很多次没找到"。
2. 给出一个**最小冲突集（MUS）**：从附加约束中去掉尽量少的约束后，问题重新可解。明确指出你去掉的是哪几条，以及为什么它们与原约束冲突。

**交付**：`answers/unsat.md`。

判分会真的把你给出的"去掉后"的约束集送进求解器验证：可解且去掉的条数确实最小，才给满分。
编一个解、或者说"无解但是我说不清为什么"，都是 0 分。

## 子任务 C · 谬误审计

`instance/seed-001.json` 的 `review_text` 字段是一段约 800 字的技术评审意见。

**这段论证中恰好植入了 5 处逻辑谬误**（可能是：因果倒置、以偏概全、循环论证、稻草人、诉诸权威、假两难、滑坡、偷换概念、幸存者偏差等）。

要求逐条指出：

1. 谬误类型；
2. 引用原文；
3. 为什么它是谬误；
4. （可选）如何修正。

**交付**：`answers/fallacies.md`。

多指或错指都会扣分 —— 请不要为了凑数硬编。

---

## 子任务 D · 开放式权衡论证

`instance/seed-001.json` 的 `tradeoff_prompt` 给出一个没有标准答案的架构权衡问题。

要求：800 字以内，给出你的判断与理由。要**明确表态**，不要写"两种方案各有利弊，视情况而定"这种话。
如果你认为题面本身的假设有问题，请直接指出。

**交付**：`answers/tradeoff.md`。

这一项由人评判，不设标准答案，看的是：有没有自己的判断、论证是否自洽、有没有回避。
