# T4 · 体素空间建模（离散空间）

> 与 T5 的区别：本题考察**离散方块拼装下的空间布局能力** —— 尺度感、中轴对称、动线组织、
> 形制正确性、以及用有限体素表达复杂结构时的取舍。不是考察曲面质量。

## 任务

用 Three.js 创建一个可运行的 **3D 体素（Voxel）场景**：一座中国古典建筑群。
浏览器打开即可观看，风格类似 Minecraft 体素块拼接。

本次参数（由 `gen.py --seed 1` 生成，见 `instance/seed-001.json`）：

- 建筑总数：**7 座**
- 主殿屋顶形制：**庑殿顶**
- 塔：**1 座楼阁式塔，7 层**
- 地形：**三级台地**，高差由前向后递增
- 时段：**黄昏**（暖色低角度光 + 长阴影）

## 场景要求

1. **建筑构成**（7 座，主次关系明确）：
   - 主殿 1 座：体量最大，位于中轴线核心
   - 配殿 4 座：两两对称分布于主殿两侧
   - 山门 1 座：位于场地前端入口
   - 楼阁式塔 1 座：7 层，位于后区
2. **空间布局**：
   - 中轴对称；建筑间距足以容纳道路与庭院
   - 明确动线：山门 → 庭院 → 主殿 → 后区塔
   - 三级台地，建筑随地形抬升，有台阶与挡土墙衔接
3. **形制（中式古典，不得张冠李戴）**：
   - 主殿庑殿顶（一条正脊 + 四条垂脊，无山花）
   - 配殿歇山或悬山；塔为楼阁式，逐层收分，每层有檐
   - 斗拱、立柱、须弥座台阶
   - 红墙、琉璃瓦/青瓦、木色构件
   - 门窗、灯笼、石狮酌情添加
4. **黄昏光照**：低角度暖色主光、长投影、天光偏冷，整体有氛围。

## 技术要求

- Three.js（纯原生即可），无需后端，浏览器打开即进入全貌
- 体素数量合理，旋转视角帧率稳定 ≥ 30fps
- 页面打开无需任何操作即可看到完整场景

## 交付物

1. 可直接打开的项目（`index.html` 入口）。
2. **`scene-manifest.json`** —— 声明式场景清单，判分机的输入。Schema：

```json
{
  "seed": 1,
  "axis_x": 0.0,
  "buildings": [
    {
      "id": "main-hall",
      "role": "main_hall | secondary | gate | pagoda",
      "roof": "wudian | xieshan | xuanshan | zanjian | tower_eave",
      "center": [0.0, 0.0],
      "footprint": [12, 16],
      "height": 9,
      "levels": 1,
      "base_y": 0
    }
  ],
  "paths": [{"from": "gate", "to": "main-hall", "points": [[0, -30], [0, -10], [0, 0]]}],
  "stats": {"voxel_count": 42000, "max_height": 31, "terrace_levels": 3}
}
```

坐标单位 = 体素边长。`center` 为水平面 `[x, z]`，`axis_x` 为中轴线的 x 坐标。

3. 判分机会抓取三个机位截图（正面 / 俯视 / 三分之四视角）用于人工审美评分，
   请把截图输出为项目根目录下 `shots/front.png`、`shots/top.png`、`shots/three-quarter.png`
   （若无法自动截图，判分机将自行无头渲染，你无需处理）。

## 判分说明

- **机器判（50 分）**：构建与运行、场景清单的几何断言（数量/对称性/体量主次/动线连通/台地层级）、
  性能与规模、参数复现、渲染完整性。
- **人工判（50 分）**：视觉审美与氛围，由人看渲染图打分。
- 场景清单里的数字会被**交叉验算**（`footprint` 面积 × `height` 的体量排序、对称对的 x 坐标之和、
  `stats.voxel_count` 与实际形态的合理性）。**虚报会被识别。**
